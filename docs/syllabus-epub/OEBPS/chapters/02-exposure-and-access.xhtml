Session 2: Exposure and Access

Goal for this session: get in the way the real intrusions of the last few years got in. No exploits, no memory corruption. A name server that tells you the whole plant, an exposed service, a default password, and an engineering workstation that hands you the keys. This is scenario 11, then scenarios 1 through 3.

2.1 Start With the Name

A real external assessment does not start with an IP address. It starts with a domain, and the first thing it asks is what the target's own name server will admit to. Cross Creek runs one, on the edge network, at 172.30.10.53, authoritative for crosscreek-water.lab and crosscreek-power.lab. In the flat topology it answers for the whole estate and it allows a zone transfer to anyone who asks.

python3 /opt/scripts/recon.py dns

That runs an AXFR against both zones and follows it with a reverse sweep of the OT segment. What comes back is the asset inventory, by function, with addresses:

plc-water.crosscreek-water.lab.    172.30.40.20
plc-dosing.crosscreek-water.lab.  172.30.40.21
hmi-water.crosscreek-water.lab.   172.30.40.10
plc-power.crosscreek-power.lab.   172.30.40.22
hmi-power.crosscreek-power.lab.   172.30.40.11
eng-ws.crosscreek-water.lab.      172.30.20.20
historian.crosscreek-water.lab.   172.30.20.30

Two things to notice. First, you now know which host is the water RO controller and which is the substation RTU without sending a single packet to either. Second, both "separate" utilities resolve eng-ws and historian to the same boxes: the water plant and the power co-op share an engineering workstation and a historian. That is a finding on its own.

You can do the same by hand, and you should know the raw commands:

dig axfr @172.30.10.53 crosscreek-water.lab
nmap -Pn -sL 172.30.40.0/24
nmap -Pn -sT -p 22,8080 crosscreek-water.lab crosscreek-power.lab

The -sL list scan does nothing but reverse-DNS every address in the range; even with zone transfers locked down, a reverse zone that maps the OT segment gives an assessor every controller's name. From here, recon.py sweep scans seven named hosts instead of walking 254 addresses. Open AXFR is one of the oldest findings in the book, and it still turns up on utility assessments, usually a legacy BIND server with allow-transfer { any; }. Notice that last nmap line does not mention Modbus, S7comm, or EtherNet/IP by port number. That omission is deliberate, and it is the subject of the next section.

2.2 Don't Assume the Port

Modbus, S7comm, and EtherNet/IP all ship with textbook default ports, 502, 102, and 44818, and every reference you will find, this book included up to this paragraph, quotes them like a fact of nature. On Cross Creek they are not there. The water PLC's Modbus port, the substation RTU's S7comm port, and the dosing controller's EtherNet/IP port have all been moved. That is deliberate: a real assessment cannot assume the vendor default either, and treating a hardcoded port list as the whole reconnaissance phase is exactly the mistake that gets written up afterward as "three PLCs, no findings."

python3 /opt/scripts/recon.py sweep

sweep still checks the textbook defaults, on purpose. Run it here and it comes back empty for all three field protocols. Whatever the name server and the reverse zone handed you in 2.1, the ports you were taught to expect are not the ports that are actually open.

The fix is the same one a real engagement reaches for: scan the whole range, not the ports you assume.

nmap -Pn -sS -p- --min-rate 2000 172.30.40.20
# 8080/tcp open, 10502/tcp open

The attacker box carries the NET_RAW capability for the SYN scan; without it, -sT does the same job, slower. Once a port is open, point nmap's own vendor scripts at it and ask what is actually listening:

nmap -Pn -sV --script modbus-discover,s7-info,enip-info -p10502 172.30.40.20

Run it, and the result is not what you would hope for. Those three scripts key off the protocol's textbook port, or a service name nmap has already recognised from its own probes, so on a moved port they usually print nothing, and -sV reports the service as unknown. That is not a broken scan, it is a limitation worth knowing before a real engagement: a scanner's convenience script is only as good as the assumption baked into it, and "the field protocol lives on its default port" is one of the most common assumptions there is. recon.py nmap runs both stages, the full range sweep and the vendor scripts, against every host the name server handed you, and reports exactly this: an open-port map, and mostly unknown labels where the field protocols are.

The reliable way to confirm what is actually listening does not come from a scanner's heuristic. It comes from talking the protocol directly, section 2.6.

2.3 The Aliquippa Pattern

The 2023 water-sector intrusions had one shape. A controller or its HMI was reachable from the internet, and it still had the credential it shipped with. CISA's advisory on the Unitronics devices spelled it out: publicly exposed, TCP port 20256, default password 1111. The fix in the advisory was not a patch. It was "disconnect it from the internet and change the password."

In Cross Creek the water HMI plays that role. In the flat topology the boundary firewall forwards everything, so from the attacker box on the edge network you can reach it, and the login page will even tell you the factory account is still active.

python3 /opt/scripts/recon.py creds
# [+] water HMI admin/admin -> ACCEPTED
# [+] power HMI admin/admin -> ACCEPTED

Now open http://127.0.0.1:8071 in your browser, log in admin / admin, and you are an operator on the SIMATIX panel. Take the loop pump 3P401 to HAND from its faceplate and stop it, and watch the loop pressure start to fall. Open the Parameter screen and move the conductivity release limit. You have the plant, from a network that in the real world would be the open internet.

2.4 The Oldsmar Pattern

Oldsmar, Florida, February 2021. An operator watched his mouse move on its own. The setpoint for sodium hydroxide, lye, went from about 100 parts per million to about 11,100. He caught it and put it back. The way in was a remote-access tool that was reachable and did not require anything to connect.

Cross Creek's engineering workstation answers a remote-desktop port with no authentication when the weakness is on.

nc -v 172.30.20.20 5900
# RFB 003.008
# Cross Creek engineering workstation - no authentication configured

That is the whole finding. A box that manages the PLCs, reachable from the IT network, that lets anyone connect. On a real site this is a jump box someone stood up "temporarily" so they could check the plant from home, on the office wifi, and never took down.

2.5 The Workstation Is the Prize

The engineering workstation is not interesting because it runs; it is interesting because of what is on it. It serves its project directory over plain HTTP.

python3 /opt/scripts/recon.py engws

That pulls notes.txt, and notes.txt is a gift:

water PLC (OpenPLC)   172.30.40.20   web openplc / openplc     Modbus 10502
dosing controller     172.30.40.21   keyswitch REMOTE          EtherNet/IP 54818
substation RTU        172.30.40.22   no station password set   S7 10102
water HMI             172.30.40.10   admin / admin
remote in from home:  VNC to 172.30.20.20 :5900  (no password ...)

It also serves water_plc.st, the golden control program. You now have the runtime login, the fact that the dosing controller keyswitch is in REMOTE, the fact that the RTU has no password, the actual field-protocol ports 2.2 sent you looking for, and a copy of the logic you will modify in Session 4. Every real assessment turns up a file like this. It is always called notes.txt or passwords.xlsx, and it is always on a share nobody remembered.

2.6 Registers Confirm What Nmap Couldn't

Nmap told you a port is open. It could not reliably tell you what is behind it, section 2.2 showed why. recon.py registers closes that gap the way a real assessor would, by acting like the HMI: it opens an actual Modbus, S7comm, or EtherNet/IP client and reads what is really there, no scanner heuristics involved.

python3 /opt/scripts/recon.py registers

Against plc-water this dumps the coils, the discrete inputs, and the holding and input registers, live numbers with no names attached, because Modbus carries no data dictionary of its own. The register map in 3.3 is what turns these numbers into 3P401 and HR_COND_LIMIT_US, and that map comes from the panel and from notes.txt and water_plc.st above, not from the wire. Against plc-power it reads DB1 as raw bytes; against plc-dosing it reads the CIP tags by the names the golden program uses. Either way, this is the confirmation nmap's generic scripts could not give you, not a guess based on a port number, but the actual protocol talking back.

2.8 What You Should Notice

You have not exploited anything. You asked a name server a question it should not have answered, found a service that was reachable when it should not have been, used a password that should have been changed at commissioning, and read a file off a share that should have had access control. That is the entire 2021-to-2024 record of public water-sector intrusions, in one session, and it is why the defense half of this course starts with segmentation and credentials before it gets anywhere near a protocol. You also stopped trusting the textbook port list along the way, which will matter every time a real deployment turns out to be configured differently than the vendor manual says. The next two sessions show you what an intruder does once they are standing where you are standing now.
