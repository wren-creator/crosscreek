Session 3: Speaking the Machines' Language

Goal for this session: talk directly to the water PLC over Modbus/TCP, with no HMI in the loop, and make the plant do things it should not. This is scenarios 4, 5, and 6. The tool is a twenty-line Python client. There is no exploit here, because Modbus does not require one.

3.1 What Modbus Is, and What It Is Not

Modbus is from 1979. It is a request-response protocol over what is now TCP port 502. A client asks to read or write coils (single bits, think relay outputs) or registers (16-bit words, think setpoints and sensor values). There is no authentication. There is no session. There is no signing. There is no sequence number an attacker cannot guess. If you can open port 502, you are, as far as the PLC is concerned, the HMI.

FrostyGoop, the malware that took the heat out of 600 buildings in Lviv in January 2024, was notable for being written in Go and for taking its target list from a config file. The Modbus part was not notable. It was function code 6, write single register, the same call your HMI makes every second.

3.2 Enumerate

python3 /opt/scripts/modbus_attack.py enum

That reads the coils, the discrete inputs, the holding registers, and the input registers and prints them. Spend a minute matching them to what you see on the HMI. Coil 0 is the intake pump. Coil 1 is the distribution pump. Holding register 0 is the chlorine dose setpoint, scaled by 100, so 250 means 2.50 ppm. Holding register 1 is the header pressure target. Input registers 0 through 4 are the live process values the HMI displays. The map is in plc/water-openplc/mapfile.py if you want the full list, but deriving it from the HMI is the exercise.

3.3 Stop the Distribution Pump (Scenario 4)

You could write coil 1 to zero, but the control program runs every 200 milliseconds and would turn it back on, because the header pressure is below target. That is a useful lesson in itself: a PLC with running logic fights you. So instead, change the thing the logic reads.

python3 /opt/scripts/modbus_attack.py stop-dist
# writes holding register 1 (pressure target) = 5 psi

Now the control loop believes the target is 5 psi, sees the actual header at 60, and holds the pump off. Watch PT-401 on the water HMI. It bleeds down at about 1 psi per second under municipal demand, and inside a minute the press_low alarm latches and the town is losing pressure. You did that with one register write, and it will hold until someone notices and puts the target back.

3.4 Overdose the Chlorine (Scenario 5)

python3 /opt/scripts/modbus_attack.py overdose 15
# writes holding register 0 = 1500  (15.00 ppm)

The residual chases the setpoint upward. Watch AIT-301 climb. Then watch it stop around 4 ppm and fall back, and the overdose alarm flag. That is the golden control program doing its job: it has an interlock that cuts the metering pump when the residual hits the safe maximum. On its own, the pure setpoint attack is contained by the PLC logic. To actually push contaminated water into the main you have to defeat that interlock, and that is Session 4. Note that for yourself: the setpoint write is the Oldsmar attack, and Oldsmar was caught. The dangerous version needs a second step.

3.5 Blind the Operator (Scenario 6)

Everything above is visible on the HMI. The alarms fire. An attentive operator acts. So the mature version of this attack hides itself. The HMI reads input registers 0 through 4. The process simulator writes the real values into holding registers 10 through 14 every second, and the PLC scan loop copies them across. If you write the mirror registers faster than the sim updates them, you control what the operator sees.

# sketch: hold the operator's view at nominal while pressure actually collapses
python3 - <<'PY'
from pymodbus.client import ModbusTcpClient
import time
c = ModbusTcpClient("172.30.40.20", port=502); c.connect()
c.write_register(1, 5, slave=1)                 # collapse the pressure target
while True:
    c.write_registers(0, [6000,7000,250,6000,4500], slave=1)  # nominal-looking IR mirror
    time.sleep(0.2)
PY

Now the header is dropping and the HMI still shows 60 psi. This is Stuxnet's operator-facing trick in miniature: record normal, replay normal, run the process to failure behind it.

3.6 What You Should Notice

Modbus gave you the plant with no credential and no exploit, and the only thing that saved the water quality was an interlock coded into the PLC program by an engineer who thought about failure. The pressure loop had no such interlock, and it fell over immediately. When you get to Session 5 you will not be able to fix Modbus, because Modbus cannot be fixed. You will fix everything around it: who can reach port 502, what the program accepts, and whether anyone would see a value that moved faster than water can.
